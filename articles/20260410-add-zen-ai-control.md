## 今日やったこと

Claude Code のスキル機能を使って、作業中のメモを自動でファイルに保存する `/add_zen` コマンドと、それをもとに Zenn 記事を生成・公開する `/zenn_post` コマンドを作った。

ざっくり言うと「思ったことをコマンド一発でメモ → 終業時にコマンド一発で記事化」というワークフローだ。面倒な日報や技術ブログの更新を、できるだけ摩擦ゼロにしたかった。

## 詰まったというか、気づいたこと

スキルファイル（Markdown に指示を書くだけ）を作って動かしてみたら、Claude はわりとちゃんと動いた。日付・時刻の取得、ファイルの新規作成と追記、フォーマット通りの出力。指示した通りに動く。

ただ、動かしてみて感じたのが「**自分、何も考えてなくないか？**」という感覚だった。

指示を書いて、Claude が動いて、結果が出る。その流れの中で、自分がどこをコントロールしているのかが、だんだんぼんやりしてくる。「自分がやった」のか「Claude がやった」のかの境界線が曖昧になる感じ。

これはたぶん、自走させすぎているからだ。一手一手の判断を Claude に任せすぎると、自分の思考が介在しなくなる。便利な反面、何か重要なことを自分で考える機会を削ってしまっている気がした。

## AIに仕事をさせる、ということ

「AIに仕事をさせる」というのは、単に指示を書けばいいわけじゃないんだと思う。どこを任せて、どこは自分で判断するか。その境界を意識して設計しないと、ただ流れに乗っているだけになる。

今回で言えば、記事のタイトルを選ぶのは自分がやっている。メモの内容も自分が書いている。でも、「それをどう構造化して記事にするか」は完全に Claude に投げていた。その部分に自分の視点が入っていないと、記事が「自分の言葉」じゃなくなる。

## まとめ

- `/add_zen` → 作業中のメモを日付ファイルに一行追記するコマンド
- `/zenn_post` → メモ＋会話コンテキストからZenn記事を生成・pushするコマンド
- 自動化は便利だが、「どこを自分が握るか」を意識しないと制御感を失う

ワークフロー自体はちゃんと動いた。次は、もう少し自分の思考が入る余地を設計したい。
